# Character pairing usability

Owner testing surfaced exact physical Bakugan whose Character dropdown offered only "No pair selected." The integrated catalogs contain 783 ordinary G2 variants, with 626 verified exact pairings and 157 without one. Loading the pinned Card Archive and Toy Archive rejected none of the 626 reviewed ordinary links. The gap was provenance coverage, not a broken selector. Only one ordinary variant (Haos Gillator Ultra, toy-1096) has two exact reviewed Character choices.

Deckbuilder release 2026-11-27-deck.8 (10c1b28) retains exact source-matched options and adds explicitly selected manual candidates for unmatched ordinary G2 variants. Same documented name or reviewed Character name, season, faction, Character type, known B-Power/damage and two recognized core symbols are required. 145 of the 157 unmatched variants now have at least one such candidate; 12 still have none. Candidate printings are not asserted to be the correct cards for those physical variants, particularly where existing source evidence is incomplete or conflicting. The dropdown labels candidates accordingly; no fallback is automatically selected. An exact archive link remains distinct from a manual choice. The team displays the stable toy ID so future coverage reports can target the right variant.

Manual selections reuse the existing profileId/cardId draft fields (manual-<card ID>), support printed-card core/faction checks, and contribute to the ownership list. The exact association remains an unknown check. An existing manual selection is not silently promoted when a verified link arrives; the user can switch to the verified option. Unmatched Fusion and support types cannot use this ordinary Character fallback. No catalog, collection schema, or Cloudflare change is required.

Verification: 142 automated tests, 64 browser smoke checks, and project lint passed, including manual selection, core autofill, persistence and a variant without any candidates.
