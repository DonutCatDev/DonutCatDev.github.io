# Exact toy profile links and paired BakuCores

Toy catalog schema 3 release `2026-11-23-pilot.5` adds separately reviewed paired cores and exact Character Card printing links for all 26 pilot G2 profiles. All 44 variant IDs, eight model IDs, 26 profile IDs, and existing toy/card base stats are preserved. The Card Archive keeps its existing schema and collection IDs.

The captured Bakulog tables name one exact card image filename per standard profile. Every selected archive record uniquely matches that filename and agrees on mold/edition, Generation 2 Character type, Battle Planet series, faction, B-Power, damage, and both cores. The mapping reviewer is identified as Codex; the review records are bound to captured table revision/content hashes, original base-fact fingerprints, selected card records, and the full pinned card-catalog SHA-256. G1 toys do not acquire guessed Character Card links. Alternate-year/regional interchangeability and format legality are outside this mapping.

This review exposed a Card Archive importer bug: its general list parser deduplicated paired BakuCores. Ten pilot profiles had lost their second repeated icon. The importer now preserves multiplicity for cores while retaining deduplication for facets. A recovery tool reconstructed repeated pairs on 405 existing G2 card records from saved exports with matching immutable ID and source revision; the candidate was checked for core-only changes before replacement. All 5,516 card IDs, other fields, images, and collection references remain unchanged. JSON public data is pinned to LF line endings so its checksums survive a fresh Windows checkout.

The card source commit is `c4810b1`. The toy mapping manifest pins the resulting `cards.json` hash `f11e7708006d67670741d84dc1c76e3caff94925de7ac407116626f9c4e8866a`. Its export checks the site's pinned Card Archive, and main-site assembly independently checks both that hash and each selected card record. A changed pin, missing card, or changed source revision/stats fails assembly. Deploy the schema 3 loader and payload together; schema 2 is rejected.

The toy details show both core icons by name, including repeated pairs, and link to the existing Card Archive ID search for the matched printing. Browser checks confirm a single expected card, its repeated pair, and Back navigation to the toy. Unmatched profiles keep unknown cores and pending compatibility. The shared stylesheet/components are unchanged; photos, product releases, broader coverage, and format validation remain future work. The catalog remains a noindex pilot.

Validation includes importer multiplicity regression tests, toy mapping/fingerprint/unsafe-input checks, a main-site test that rejects a checksum-valid toy snapshot with an incorrect card dependency pin, and browser coverage of reviewed/pending states and cross-archive navigation. Manual push order is Card Archive, Toy Archive, then main site. No remote changes or publication are part of this work.
