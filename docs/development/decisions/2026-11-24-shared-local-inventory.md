# Shared local Bakugan inventory pilot

The collection manager lives in a separate sibling repository, `S:/Bakugan/website_stuff/bakugan_collection`, and is assembled from `vendor/bakugan_collection/public/` at `/baku/collection/`. The main-site build verifies its public checksum manifest and emits the same pinned Card Archive stylesheet used by the Toy Archive. The route remains noindex; collection data is not part of the site artifact.

The proposed remote for the new submodule is `https://github.com/DonutCatDev/Bakugan_Collection.git`. The local repository and gitlink can be validated before that remote exists. The owner must create or provide access to that remote and push the pinned collection commit before pushing the site. The Pages checkout credential (`BAKUGAN_ARCHIVE_TOKEN`) must be able to read all referenced private repositories. No remote was created or changed during implementation.

## Contract and ownership

- `bakugan-suite.inventory.v2` is the canonical adopted browser-local inventory. Entries have kind-scoped stable catalog IDs, independent owned/wanted/offered quantities, a bounded recovery snapshot and optional private notes. Binder IDs are stable; memberships reference entries and do not duplicate quantities. The manager exposes ordered logical binders, grid/list search, totals, filtered Have/Want/Trade lists and versioned backups.
- Before adoption, the existing Card Archive v1 key stays authoritative for its old controls. The manager reads it without changing it, previews matched/unmatched data and offers the original JSON. Activation is explicit, verifies the source bytes, and leaves v1 untouched. Reload old tabs from before the deployment before activating.
- After adoption, Card Archive controls read/write only the card-owned projection through the shared module served at `/baku/collection/scripts/lib/inventory.js`. A card-only import does not replace toys, wants, offers, notes or binders. The manager is the editing surface for full-suite quantities and binders. Toy details hand off an exact variant ID to the manager rather than maintaining a second local store.
- All writes to adopted storage use one Web Lock and compare the prior serialized state, then reread persisted bytes for verification. This keeps two updated tabs from silently overwriting each other's edits. The UI preserves drafts on errors and asks for a fresh preview for changed imports. Browsers without Web Locks can browse/export but cannot safely adopt/write the shared store; legacy-only card editing remains supported prior to activation. Storage events refresh views. The store is local to an origin and browser profile; it does not promise cross-device or server backup.
- Import validates the full model, previews counts, preserves unmatched IDs, then applies explicit Merge or Replace. Merge takes maximum quantities and unions binder memberships; it never sums duplicate copies. Shared recovery requires a complete suite backup rather than silently replacing unreadable shared data with a card-only file. Outstanding offered quantities must be explicitly resolved before reducing ownership.
- Local list downloads contain only names, set/serial, kind and relevant quantity. Full JSON includes private notes and binders; these are distinct export actions. Nothing is automatically published or sent. Accounts, synchronization, and hosted share snapshots remain later work.
