# Baseline engineering audit

Date: 2026-10-27

## Project shape

donutcat.org is a dependency-free GitHub Pages single-page application. `index.html` supplies the document shell and route templates, `scripts/app.js` handles History API routing, feature scripts render interactive pages, and `404.html` hands deep links back to the SPA.

## Primary findings

1. Repository instructions and contributor documentation are incomplete. Guidance exists only in `.github/copilot-instructions.md`.
2. The two spreadsheet grid implementations duplicate roughly 1,100 lines and load an unpinned ag-Grid release at runtime.
3. Spreadsheet values can become HTML strings in grid cell renderers. External data should instead be rendered with DOM APIs and validated URLs.
4. Feature scripts have no explicit mount/unmount lifecycle, so repeated SPA navigation can duplicate scripts, styles, listeners, and third-party instances.
5. The prizing calculator mixes business rules with DOM updates and has no regression tests.
6. SPA navigation does not update page titles, active navigation state, focus, or route announcements.
7. Embedded pages need accessible titles, loading behavior, fallback links, and more useful error handling.
8. The document lacks descriptions, canonical URLs, social metadata, a sitemap, robots policy, and structured data.
9. The project has no automated formatting, linting, unit testing, browser testing, accessibility checking, or CI.
10. The single 315 by 337 image is stretched across several presentation contexts and needs an intentional responsive asset strategy.

## Approved implementation scope

Implement phases 0, 1, 2, 3, and 5 from the initial audit:

- Phase 0: governance and repository baseline.
- Phase 1: reliability and security.
- Phase 2: calculator correctness and tests.
- Phase 3: accessibility and navigation.
- Phase 5: SEO, sharing, and discovery.

Document phases 4, 6, and 7 in depth for later implementation, then perform a new audit after the implemented phases are complete.

## Constraints

- Preserve GitHub Pages and the custom domain.
- Preserve the established site voice and navy/light visual identity.
- Avoid a framework migration.
- Do not change payout business rules without documenting and testing the rule.
- Do not publish or push; prepare local commits for manual review and push.
